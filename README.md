# Verified Cloudflare publisher

The private controller builds and tests the application, verifies the deployable files, and retains its artifact. This repository contains the publisher and its synthetic tests. The publishing workflow downloads the verified archive into a temporary directory, checks its GitHub digest and deployment bindings, and emits only fixed status messages. It does not upload workflow artifacts.

Protect `main` with required pull requests and the `test` status check. Restrict the `production` environment to the protected `main` branch before supplying any secret. Store `SOURCE_REPOSITORY`, `SOURCE_WORKFLOW_SHA`, `WORKER_NAME`, and `CLOUDFLARE_ACCOUNT_ID` as environment secrets so the public runner masks their values. Keep the approved private controller commit pinned until the next reviewed revision.

Install the handoff GitHub App on the private controller only and grant it Actions read access. For each protected environment, store its client ID as the `HANDOFF_APP_CLIENT_ID` variable, its private key as `HANDOFF_APP_PRIVATE_KEY`, and the controller repository name without its owner as `HANDOFF_APP_REPOSITORY`. The workflow mints a short-lived token for that repository at run time. Store `WORKER_DATABASE_ID` and any Worker-scoped `CLOUDFLARE_API_TOKEN` in the corresponding protected environment. The Cloudflare key is passed only to the explicit deploy step. Run verification using `publish=false` before granting the Cloudflare key.

For isolated validation, run the same workflow from protected `main` with `isolated=true` and `publish=false`. Use a protected `handoff-validation` environment restricted to `main`. Supply the App settings, source metadata, and `SOURCE_WORKFLOW_BRANCH` for the approved isolated controller branch. The Worker and D1 settings must be fixtures. The isolated job has no Cloudflare credentials and cannot deploy. Its ZIP and unpacked data each have a 32 MiB limit.

The `bound_worker` option selects `bound-worker-production`, restricted to protected `main`. Pin the approved controller branch and commit separately. This profile verifies and deploys a Worker with an existing D1 binding and preserves server-side login settings with `keep_vars`. It uses the same 32 MiB limits as isolated verification and requires an explicit publish input for deployment.
